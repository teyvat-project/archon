# Archon M6（Go）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Go 1.22+ 言語プラグインと、標準ライブラリだけに依存する手書き Go ランタイムを実装する。`edge-cases.yaml` と `natsuneko.json` から生成した Go SDK が `go vet` / `go build` を通り、`gofmt -l` が空（生成物がそのまま gofmt 済み）で、TypeScript / C# / Kotlin と同じ E2E シナリオがモックサーバに対して通ることを完了条件とする。

**Architecture:** `runtimes/go` を Go モジュール（`go.mod` は `runtimes/go`、パッケージ `core` のソースは `runtimes/go/src`）として置き、生成時に出力先 `core/` へそのままコピーする（パッケージ名は両方 `core` なので書き換えは無い）。Go プラグイン（`packages/archon/src/plugins/go`）は inline の object / enum / union を巻き上げた IR から、出力ルートの 1 パッケージにモデル（`<snake>_model.go`）、タグ別サービス（`<snake>_service.go`）、`client.go` / `auth.go`、`go.mod` を出力する。E2E は既存の `e2e/mock-server` を Node スクリプトで起動し、生成 SDK を `replace` で取り込む Go テストモジュール `e2e/go` を `go test` で実行する。

**Tech Stack:** Go 1.22+（`go.mod` の `go 1.22`。開発機は Go 1.27 で、CI は 1.22 と stable の両方でランタイムを検証）、既存の Node 24 / pnpm 10 / vitest / jiti。

**Spec:** `docs/superpowers/specs/2026-10-25-archon-design.md`（§6 生成 SDK 共通仕様、§7 Go 列、§8 認証、§10 テスト戦略）。挙動の規則は M2 / M3 と同じものを Go に写し、ここでは差分だけを書く。

## Global Constraints

- 生成 SDK とランタイムの依存は Go 標準ライブラリのみ（`net/http`、`encoding/json`、`context`、`time`、`sync` 等）。`reflect` は `encoding/json` と同じく使ってよい。Go 1.22 より新しい標準 API は使わない（CI の Go 1.22 ジョブで保証）。
- 生成物は `go vet ./...` が通り、`gofmt -l .` が空であること。プラグインは gofmt の整形（構造体フィールド・const グループ・複数行 keyed literal の桁揃え、トップレベル宣言の doc comment の正規化）を自前で再現する（`align.ts`）。
- API 形状（spec §7）: `client.Echo.EchoPathStyles(ctx, params, opts...)`。第 1 引数は `context.Context`。戻り値は `(T, *http.Response, error)`（no-content の操作は `(*http.Response, error)`）。
- Middleware（spec §6.2）: `type Middleware func(req *Request, next Next, ctx *CallContext) (*Response, error)`、`type Next func(req *Request) (*Response, error)`。登録順に外側から実行し、認証適用は最内側。
- 型対応（spec §7 Go 列）: `date-time` → `time.Time`、`int64` → `int64`、`uuid` / `uri` → `string`、nullable / optional → `*T` + `omitempty`（スライス・map・`json.RawMessage` はポインタにしない）。
- 判別あり union → 構造体 + 自前 `UnmarshalJSON`（判別値で選ぶ）、判別なし union → 順に試す、enum → `type X string` + 定数（spec §7）。予約語は末尾 `_`。
- 標準 middleware・認証・OAuth2・リダイレクト時の資格情報除去・再送可能リクエスト・パラメータ直列化（バイト単位）の規則と既定値は TS / C# / Kotlin と同一。
- requestBody の media type 優先順は json > multipart > form > text > binary（IR で並べ替え済み、`contents[0]` を採用）。
- 生成物の各ファイル先頭は `// Code generated by Archon. DO NOT EDIT.`（Go の生成物判定の慣習）と生成ヘッダ（`output.header` で上書き可）、空行、`package`。

## Spec からの M6 における意図的な差分

- **params は 1 つの構造体、body は別引数**: spec の `GetX(ctx, params)` に従い、パラメータを持つ操作は `<Method>Params` 構造体を値で受ける（必須は `T`、任意は `*T` / スライス / map）。body は `params` に入れず、その後ろの引数にする（必須は `T`、任意は `*T` で `nil` なら送らない）。`EchoJson(ctx, JsonPayload{...})` のように書けるため。リクエスト単位の設定は可変長の `opts ...core.RequestOption`（`core.WithHeader` / `core.WithBaseURL` / `core.WithExtension`）。
- **成功 JSON の戻り値型**: object / union のモデルは `*T`、それ以外（スライス・map・スカラー・enum）は値。204 / 空 body は nil を取れる型（ポインタ・スライス・map・`json.RawMessage`）ならゼロ値、取れない型なら `*core.DecodeError`（C# と同じく「空 JSON」シナリオは nil を返す）。
- **`*http.Response` は読み込み済み**: ランタイムが body を全量読むので、返す `*http.Response` の `Body` は読み込んだバイト列の `io.NopCloser`（何度でも読める）、`Request.URL` は最終 URL。非 2xx でも `*http.Response` を返す（go-github と同じ）。
- **エラー型**: `*core.APIError`（`StatusCode` / `Header` / `RawBody` / `URL` / `Body any`。宣言された型のボディは `*T` で入るので `apiErr.Body.(*NotFoundError)`、または `core.ErrorBody[*NotFoundError](err)`）、`*core.TransportError`（`Timeout`、`Unwrap`）、`*core.DecodeError`、`*core.AuthError`。すべて `errors.As` で取り出す。呼び出し側の `ctx` のキャンセル / 期限切れは `TransportError` で包むが `errors.Is(err, context.Canceled)` が成り立つ（`Timeout` は `ClientOptions.Timeout` の経過だけ）。
- **必須プロパティの検査**: `encoding/json` は必須を検査しないので、必須プロパティを持つ object には `UnmarshalJSON` を生成し、キーの欠落と non-null 必須の `null` を `error` にする（C# の `required` / Kotlin と同じ。判別なし union が Cat と Dog を取り違えないためにも必要）。
- **union は「バリアントごとのポインタ + Raw」の構造体**: `type Shape struct { Circle *Circle; Square *Square; Raw json.RawMessage }`。どれにも当たらなければ `Raw` に生 JSON を保持し、書き込み時はそのまま返す。判別プロパティはバリアントに残し、マップ先のタグがちょうど 1 つのバリアントには空のときにタグを補う `MarshalJSON` を生成する（`Circle{Radius: 1}` で `"kind":"circle"` が出る）。バリアント間の参照は常にポインタなので、union を介した自己参照は値型で書ける。
- **enum は名前付き型 + 定数 + `IsKnown()`**: `type Status string`、`StatusActive Status = "active"`、未知の値もそのまま保持・再送できる（spec §6.6）。integer は `int64`、number は `float64`。
- **必須の object 参照は値型**: ただし値型だけで循環する場合（`A.b: B` と `B.a: A` が両方必須）はポインタにする（Go は無限サイズの型を許さない）。
- **`date` は `core.Date`**（`YYYY-MM-DD` を読み書きする小さな型）。spec の表に無い format なので、`time.Time` に寄せて時刻が付くのを避ける。`format: byte` は `[]byte`（`encoding/json` が base64 で読み書きする）、`binary` は `core.File`（`Content []byte` + `Name` + `ContentType`、JSON 内では base64）。spec の `io.Reader` は再送可能性（§6.2）と両立しないので、`core.ReadFile(r, name, contentType)` で読み込んで渡す。ストリームで送りたい場合は `core.ReaderBody`（`Replayable() == false`）を `core.WithBody` で使う。
- **未知の schema は `json.RawMessage`**（生 JSON を保持。Kotlin の `JsonElement` と同じ扱い）。
- **ClientOptions は生成時に固定**: `NewClient(ClientOptions{...})` は値をコピーし、以後の変更は `client.Use(mw)` だけ（Go の慣習）。ただし `Auth` はポインタなので、スキームの値を差し替えると次の送信から使われ、OAuth2 のトークンマネージャは値（`*core.OAuth2`）が変わったら作り直す。
- **ヘッダは `http.Header`**（Go の慣習）。ログのヘッダ行は名前順。

## Review Focus

- **net/http による URL の書き換え**（query `piped=1|2&filter[a]=b&x=%41`、path の `%2F` / `%41`）→ `url.URL{Opaque: path, RawQuery: query}` でリクエスト行がランタイムの直列化結果とバイト単位で一致する。→ Task 2 のテスト。
- **利用者が渡した `*http.Client` が `CheckRedirect` / `Jar` を設定済み**→ ランタイムは `CheckRedirect` を `http.ErrUseLastResponse` に差し替えた浅いコピーで送り、手動リダイレクトで cross-origin の資格情報が除去される。利用者の client は変更しない。→ Task 2。
- **gofmt と一致しない出力**（構造体の桁揃え、コメント行で切れる揃え、複数行 literal、doc comment のリスト / インデント / 連続空行）→ compile テストで `gofmt -l` が空。→ Task 5、Task 7。
- **Go の識別子として不正・衝突する名前**（プロパティ `x-foo` / `2fa` / `foo_bar` と `fooBar`、schema `1Thing` / `Client` / `Auth` / `String` / `Error`、group `core` / `use`、`MarshalJSON` という名前のプロパティ、ファイル名が `_test` / `_windows` / `_amd64` で終わる schema、json タグにできないワイヤ名）→ 正規化・接尾辞・警告で `go vet` が通る。→ Task 5、Task 7（stress）。
- **自己参照 / 相互参照と循環 union**（`Node.children []Node`、`U1 = U2 | string` / `U2 = U1 | int`、値型の循環）→ コンパイルが通り、読み込みが無限再帰しない。→ Task 5、Task 7。
- **同時リクエストとキャンセル**（コールドクライアントで 5 並行、1 つの ctx を途中で cancel、`Timeout` 経過と ctx の cancel の区別）→ トークン取得は 1 回、cancel した呼び出しだけが `context.Canceled`、残りは成功。→ Task 2、Task 3、`go test -race`。
